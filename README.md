## 操作指示は5種類、学習するクラスは6種類

Teachable Machine のクラス名は、次の表のとおり**漢字で**入力します。操作ページはクラス名で送る指示を決めます。

| クラス名 | 送る文字 | 外付けLED（D2） | サーボ（D9） | LEDマトリクス |
|---|---|---|---|---|
| `点灯` | O | 点灯 | そのまま | 光っている丸 |
| `消灯` | F | 消灯 | そのまま | 中が空の丸 |
| `右` | R | そのまま | 右（0°） | 右向きの矢印 |
| `上` | C | そのまま | 中央へ戻す（90°） | 上向きの矢印 |
| `左` | L | そのまま | 左（180°） | 左向きの矢印 |
| `待機` | 送らない | そのまま | そのまま | そのまま |

- 「上」のポーズは、この作品では「サーボを中央へ戻す」操作に割り当てています（「中央」という意味の手話ではありません）。
- 「点灯」「消灯」ではサーボを動かしません。「右」「上」「左」では LED を変えません。例：点灯 → 右 の順に指示すると、LED は点いたまま、サーボだけが右へ動きます。
- 「待機」は、手を下ろした状態や、操作用のポーズをしていない状態を撮ります。待機と判定したときは新しい指示を送らず、LED とサーボは直前の状態のままです。待機クラスを用意しても、誤認識が完全になくなるわけではありません。
- LED マトリクスには、Arduino に届いた指示の記号が出ます。記号が変われば、指示は Arduino まで届いています。
- 上の表以外の名前のクラスは「送らない」になります（Teachable Machine側で名前・画像を直して再学習・更新します）。

## 学習の進め方

1. 1時間目：「点灯」「消灯」「待機」の3クラスで、画像の収集・学習・テストを体験する。
2. 2時間目 ステップ1：LED 1個を配線し、AI で点灯・消灯する。
3. 2時間目 ステップ2：サーボを配線し、同じプロジェクトに「右」「上」「左」を追加して学習し直す（6クラス）。クラウド上のモデルを更新し、操作ページで「モデルを再読み込み」を押す（共有リンクは通常同じです）。

Arduino のプログラムは途中で書き換えません。

## 手話とポーズ

- 授業のスライドでは、参考動画の表現を「操作用ポーズ」のお手本として紹介しています（右・上・左：https://www.youtube.com/watch?v=qlnuVcSbHsA 、点灯・消灯：https://www.youtube.com/watch?v=dZBdf1NM1g0 。後者の動画タイトルには「ASL」とあり、日本の手話とアメリカ手話は別の言語です）。画像だけで言語や正式な意味を決めず、動きや意味は元の動画と先生の確認に合わせます。
- お手本の画像は学習させません。生徒自身の姿をカメラで撮影して学習させます。
- 操作に使う手話・ポーズは、生徒と先生で確認して決めます。手話の表現を使う場合は、先生や信頼できる資料で確かめたものだけにします。
- 自分たちで決めたポーズは「ジェスチャー」と呼び、正式な手話として紹介しません。
- このAIは画像分類です。カメラの画像1枚ごとに「どのクラスに近いか」を見分けるだけで、動きのある手話全体を理解・翻訳する仕組みではありません。止まった形で見分けられるものを使います。

## AIが見分けやすくなる画像の集め方

AI は、手の形だけでなく、顔・服・背景・明るさを手がかりにしてしまうことがあります。

- 同じ人・同じ場所で、全部のクラスを撮ります。条件を変えるときは、全クラスで同じように変えます（例：全部を明るい所と暗い所で撮る）。
- 指先から腕まで写るようにします。逆光、ポーズの途中、同じ画像ばかりは避けます。
- 実際に操作する距離で撮ります。手のアップだけで学習しないようにします。
- 撮影の手順：
  1. 手と腕が入るようにカメラの位置を決める
  2. お手本を見てポーズを作る
  3. ポーズができてから撮影を始める（Hold to Record）
  4. 撮影を止めてから手を下ろす
  5. 位置や角度を少しずつ変えて、何回かに分けて撮る
  6. 見直して、違う画像を消す
- 変化を付けても、指の形や向きは変えません（別の意味のポーズになるほど変えない）。
- 「待機」には、手を下ろす・画面を見ている・少し姿勢を変える、などを撮ります。**5つの操作用ポーズの画像を待機に入れません。** 待機があっても、まちがいはゼロになりません。
- 自分が操作するもの（今回の基本）は、まず自分で全種類のポーズを撮ります。複数の人が操作するもの（発展）は、複数の人がそれぞれ全種類を撮ります。
- 大事なのは枚数だけではなく、正しいラベル・画像の多様さ・実際の使用条件です。

## 学習したら、ポーズを作り直して試す

1. まずは Teachable Machine の Preview で、合図ごとに試します（操作ページでは、Arduino につなぐ前か「一時停止」にすると、送らずに判定だけを見られます）。
2. 一度手を下ろしてから、ポーズを作り直して試します（少し位置がずれても認識するか、手を下ろすと「待機」になるか、どれとどれを間違えやすいか）。
3. 間違えたら：クラス名・画像の混入を確かめる → 苦手な条件の画像を追加 → もう一度学習する → 新しくポーズを作って試す。
   - 苦手な距離・位置・向きの画像を追加する／間違ったクラスに入れた画像を除外する／手が写っていない画像や撮影途中の画像を確かめる／必要ならクラスを作り直して撮り直す／同じ画像ばかり増やさず、使う範囲で変化をつける／クラス間の枚数を極端に偏らせない。
   - 正しい合図が写っている難しい画像を、認識率を上げるためだけに消さない。

試して、間違いを見つけ、改善することも実習の一部です。

## 配線

| 部品 | Arduino のピン |
|---|---|
| LED 1個（ステップ1） | D2 → 抵抗 → LED の＋（長い足）、LED の−（短い足）→ 青い−レール → GND |
| サーボ（ステップ2） | 信号（ふつうオレンジ）→ D9、＋（ふつう赤）→ 5V、−（ふつう茶）→ GND（第3回と同じ） |
| LED マトリクス | 本体（配線なし） |
| LED を追加（発展） | D3・D4・D5・D6（それぞれ 抵抗 → LED → GND） |

- ブレッドボード：LED の両足は a〜e の中の、別々の番号の列に差します（電源レールにまたがって差さない）。青い−レールは Arduino の GND へ。赤い＋レールは LED には使いません（サーボの電源などに使うときは 5V へ）。レールが途中で分かれている製品は、使う区間を線でつなぎます。
- 各 LED は自分のピンから信号線を引きます（D2 を HIGH で点灯、LOW で消灯）。
- LED ごとに抵抗を1個入れます（1kΩ を候補。UNO R4 WiFi の I/O ピンは1本 8mA まで）。
- 配線を変えるときは、必ず電源を外してから行います。
- サーボの電源は第3回と同じく Arduino の 5V・GND から取ります（講師が使用するサーボで事前に確認する構成）。動作が不安定なとき（リセットする・震える）は、講師に知らせてください。

## サーボの向き

サーボを軸（ホーン）が上になるように置き、上から見たときの向きです。多くのサーボは角度の数字が大きいほど反時計回り（左回り）になるので、初めの値は 右＝0°、中央＝90°（クラス「上」）、左＝180° です。
左右が逆に動くときは、`ANGLE_RIGHT` と `ANGLE_LEFT` の数字を入れかえます。起動したときは中央（90°）になります。

## dai4_ai_remote で変えるところ（「★ここを変える」の中だけ）

| 名前 | 初めの値 | 意味 |
|---|---|---|
| `DEVICE_NAME` | `"NGS-01"` | 機器名。先生から割り当てられた自分の番号（NGS-01〜NGS-11） |
| `ANGLE_RIGHT`・`ANGLE_CENTER`・`ANGLE_LEFT` | `0`・`90`・`180` | サーボの角度（0〜180） |
| `PICTURE_ON`・`PICTURE_OFF`・`PICTURE_RIGHT`・`PICTURE_CENTER`・`PICTURE_LEFT` | 丸・空の丸・矢印 | 届いた指示の記号（`#` が光る、`.` が消える。横12文字×縦8行）。余裕があれば描きかえてよい |

- `servo.attach(9)` は信号を出すピンの指定（setup で1回）、`servo.write(角度)` は角度の指定です。
- 発展：`handleCommand` の中の各ブロックに1行足して動きを組み合わせます。
  - `ledOnly(YELLOW);`：その LED だけを光らせる（色は RED・YELLOW・BLUE・GREEN・WHITE）
  - `ledSequence();`：D2→D6 の順に光らせる（例：点灯のブロックに足す）
  - `ledOnly`・`ledSequence`・`showPicture` はこの教材で用意した関数で、`servo.write` はServoライブラリ、`digitalWrite` はArduino標準の命令です。

## 操作ページ（index.html）の使い方

1. Teachable Machine（https://teachablemachine.withgoogle.com/ 。検索で「teachable machine」と入力しても開けます）で学習したら、「Export Model」→「Tensorflow.js」→「Upload (shareable link)」→「Upload my model」を押し、表示された共有リンクをコピーする。
2. index.html を Chrome で開き、①の欄にリンクを貼り付けて「モデルを読み込む」。
3. ②「カメラを使う」→ カメラの使用を「許可」。合図を出してバーの長さを確かめる。クラスごとに送る命令が表示される（待機は「送らない」）。
   - Teachable Machine の撮影欄を×で閉じ、PreviewのInputをOFFにします。追加学習に使うので、TMのタブは閉じません。
4. ③「Bluetoothで接続」→ 一覧から自分の機器を選ぶ。①②の準備ができていれば、**つながると自動で「AI操作中」になります**（「AIで操作」を押す手順はありません）。
- 状態の表示：「未接続」「準備待ち」（モデル・カメラの準備ができていない／モデルを読み込み中）「AI操作中」「一時停止中」。
- 「一時停止」で止め、「再開」で戻します。「手で試す」のボタン（点灯・消灯・右・上・左）を押すと、AI操作は一時停止します。切断すると送信は止まります。
- 判定だけを見たいときは、Arduino につなぐ前（未接続）か、「一時停止」にして見ます。
- PC の画面（1366×768 程度）で、スクロールしなくても③の「Bluetoothで接続」まで見える配置です（左の列：①②③と状態、右の列：カメラと判定）。送る条件と説明は下の「詳しい設定と説明」に折りたたんでいます。
- カメラ映像は鏡のように左右反転して表示されます。見た目で左右を決めず、「AIの判定」の表示と、実際のサーボの動きで確かめます。

### 送る条件（初めの値）

- **同じクラスが、スコア 0.70 以上を 0.5 秒続けたときに送ります。**
- 途中で別のクラスになったり、スコアが 0.70 を下回ったりすると、時間の計測は最初からやり直します。
- 同じ命令は続けて送りません（判定が変わったときだけ送る）。待機が続いたあとは、同じ命令でももう一度送れます。
- つながった直後・再開した直後・モデルを読み込み直した直後は、前の判定を使わず、新しく 0.5 秒続いてから送ります。
- スコアは「どのクラスに近いと判定したか」の目安で、必ず正しい確率ではありません。
- 操作ページは AI のライブラリ（TensorFlow.js 1.3.1・Teachable Machine image 0.8）とモデルをインターネットから読み込みます。**授業中はインターネットが必要です。**

### クラス名

- 送る命令は、クラスの並び順ではなく**クラス名**で決まります（点灯・消灯・左・上・右・待機）。
- 「Class 6」など決まった名前ではないクラスは送りません。Teachable Machine で「待機」などに名前を直してください（Class 6 に待機の画像が入っているとは限りません。名前を「待機」に変えて、待機の画像を集めます）。

### モデルを更新するとき（2回目から）

1. 操作ページのAIを「一時停止」し、②「カメラを止める」を押す。TMのタブへ戻り、画像を追加・整理して学習し直す。
2. 「Export Model」を開く。
3. 「Update my cloud model」でクラウド上のモデルを更新する（共有リンクは同じまま）。
4. 「Your cloud model is up to date.」と出たことを確かめる。
5. TMの撮影欄を×で閉じ、PreviewのInputをOFFにする。操作ページで「**モデルを再読み込み**」→「カメラを使う」→「再開」。Bluetoothが切れていれば③で再接続する。新しいURLの場合は欄に貼って「モデルを読み込む」を押す。

- Teachable Machine で学習し直しただけでは、共有リンクのモデルは更新されたとは限りません。3・4 まで行います。
- 「モデルを再読み込み」は、キャッシュを使わずに model.json・metadata.json・重みファイルを取り直します（全ファイルのURLに読み込みごとの識別子を付け、fetchのcache: no-storeを明示。複数の重みファイルにも対応）。
- 読み込み中は命令を送りません。読み込みに成功してから新しいモデルに切り替え、古いモデルはメモリから解放します。判定のくり返しは1つだけです。
- 読み込んだ時刻・モデルの日時（metadata.json の timeStamp）・クラス数を表示します。日時が前と同じなら注意を表示します。日時だけでモデル内容が同一だとは断定しません。
- 失敗したときは成功表示にせず、理由（見つからない＝URL違いやアップロード未完了、取得できない＝インターネット など）を表示します。前のモデルがあるときは、前のモデルのまま一時停止します。
- 反映されないとき：更新完了とURLを確かめる → 「モデルを再読み込み」→ 必要なら操作ページを開き直して、モデル・カメラ・Bluetooth を設定し直す → それでも直らなければ、Chrome のキャッシュ削除や、新しくアップロードして新しい URL を使うことを検討する。

## 使うときのきまり

- 書き込むとき：PC と Arduino を USB でつなぐ（書き込みと電源）。
- AI で動かすとき：PC の USB を外し、Arduino を USB 充電器などにつなぐ。LED マトリクスに番号が出てから接続する（つながるとチェックの絵になる）。
- コードを直すとき：「切断」→ USB 充電器から外す → PC と USB でつなぐ → 直して書き込む → USB 充電器につなぐ → 接続し直す。
- Bluetooth の設定画面でのペアリングは不要です。
- 第3回の操作ページとは別の番号（UUID）を使っています。第3回の index.html では第4回のプログラムにつながりません。

## 今回の確認・修正（2026-11-22）

- 0.70以上・0.5秒、接続成功後のAI自動開始は元から実装済み。
- ②に「カメラを止める」を追加。TMのタブを残して追加撮影できるようにしました。

- 一時停止・カメラ停止・モデル読み込み等の後は、まだ実行していないAI送信を取り消します。送信済みの命令や開始済みのBluetooth書き込みを取り消すものではありません。
- READMEの手順を修正版スライドに合わせました。Arduinoの配線・命令・スケッチは変更していません。
